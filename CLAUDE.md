# mcp-arcade-cabinets

Read `HANDOFF.md` first. That is the pick-up.

Games on top of mcp-arcade (sister repo, `E:/AI/mcp-arcade`). Cabinets **read tapes** (`mcp-arcade.tape/v1`) and write nothing the instrument, the oracle, or the dataset ever sees. They do **not** load receipts. The instrument lock (C1–C9 over there) is closed and is not reopened here.

Two cabinets, both shipped at **v0.10.0** (2026-09-16), each as its own npm package. **Ghost on the Menu** (replay shooter). **Vibe Typer** (typing arcade game: you are a sycophantic coding agent, the user is a vibe coder, you type the code and the thing gets built): slices 1 and 2 landed 2026-09-15; slice 3 (`docs/vibe-typer.kickoff-s3.md`: content authored by a writing model from voice sheets, check-ins, a model-based endless that writes code behind a code gate, American English, the settings row, the logo and device frames, sixteen story levels, one package per cabinet) shipped 2026-09-16 as v0.10.0, its build in `docs/vibe-typer.slice3.md`; slice 4 is `docs/vibe-typer.kickoff-s4.md` (the container tools so `--mcp` on the Vibe package means something, the rest of the look, the voice on the user's lines, beds per stack). Its lock is G23–G30 in `docs/vibe-typer.dispatch.md` (G28 amended by the slice-3 kickoff) and it takes Ghost's chassis, never its grammar (no lamps, waves, bosses, shift, lies or tape schedule). The agent's default name is Sprocket. House Call (turn-based calibration) was parked by the Director on 2026-09-10 because it was not fun; last state `152f548`. It comes back only when there is a design that plays. `tape-core` keeps the scoring rules for that day. Deferrals for the next pass live at the top of `HANDOFF.md` (translations, Comfy polish, `archivist.mp3`, health leftovers).

Cabinet lock: G1, G7, G8, G9, G10 in `docs/study-swarm.dispatch.md`. Version stays `0.x` until the Director says otherwise. Do not promote to 1.0.0 because it is a release.

**Two packages publish to npm, one per cabinet, and no bundle (the Director's decision, 2026-09-15; sub-slice F of `docs/vibe-typer.kickoff-s3.md`, landed on `main` the same day).** `packages/launcher` publishes as `@mcptoolshop/ghost-on-the-menu` (Ghost only: `npx` serves Ghost with the local seats lit; `--mcp` is the stdio cabinet server) and `packages/launcher-vibe-typer` publishes as `@mcptoolshop/vibe-typer` (Vibe Typer only: `npx` serves it on port 7778 with the endless seat lit; `--mcp` exits 2 naming slice 4 until the container tools exist). `0.9.0` had shipped both cabinets inside the Ghost package, which made the name wrong. The two packages share one pack script (`packages/launcher/scripts/build.mjs --cabinet ghost|vibe`), one marker gate per package and one `release.yml` that publishes both under one version gate with an idempotent loop; Trusted Publishing is per package, keyed to that filename, no environment. `tape-core`, `ghost-on-the-menu`, `vibe-typer`, `cabinet-server` and `cabinets` stay `"private": true` and go nowhere near a registry; the `@mcp-arcade-cabinets/*` scope is not an npm scope; `@mcptoolshop/mcp-arcade-cabinets` is not reserved and nothing publishes under it. Both launchers carry no runtime dependencies on purpose — esbuild bundles the workspace in. Do not add a `dependencies` block to either, and do not publish a third package without the Director's word. Everything else is unchanged: git tag + GitHub release + Pages + GHCR. Read `docs/npm-launcher.md` before touching the publish path; its compensators table is binding, and note that **cutting a GitHub release publishes both packages to npm**, which is not undoable after 72 hours.
