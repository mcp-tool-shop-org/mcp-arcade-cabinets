**The word list.** `BRITISH` is 50 entries, each a `{ word, re }` where `word` is the American form the

### The type sizes, and the wrap arithmetic

| Word     | `--vibe-font` | at 16px root |
| -------- | ------------- | ------------ |
| `small`  | `0.9rem`      | 14.4px       |
| `medium` | `1.05rem`     | 16.8px       |
| `large`  | `1.25rem`     | 20px         |
| `huge`   | `1.5rem`      | 24px         |

`large` is the default, and it is 32% bigger than the `0.95rem` that shipped in v0.9.0, which is the point of
the setting. `small` is deliberately still a shade under what shipped, so the word means something.

**The pane at 1280.** `main.playing` is `padding: 1rem 2rem` with no max width, so the content box is
1280 − 64 = **1216px**. `.vibe-panes` has two 0.75rem gaps (**24px**) and a third column of `auto` — the
preview pane, 480px of canvas plus 0.5rem of padding a side and a 1px border a side = **498px**. That leaves
1216 − 24 − 498 = **694px** for the chat and the editor.

- Before: `minmax(12rem, 1fr) minmax(16rem, 1.4fr)` — minimums 192 + 256 = 448px, both satisfied, so the free
  space splits by the fractions: chat 694 × 1/2.4 = 289.2px, editor 694 × 1.4/2.4 = **404.8px**. Inside the
  editor's 0.6rem padding and 1px border, the text box is 404.8 − 19.2 − 2 = **383.6px**.
- After, at ≥ 1280px: `minmax(10rem, 0.8fr) minmax(24rem, 2fr)` — minimums 160 + 384 = 544px, still satisfied,
  so chat 694 × 0.8/2.8 = 198.3px, editor 694 × 2/2.8 = **495.7px**, text box **474.5px**. The editor gains
  90.9px, about 24%, and it gains it out of the chat, which is prose and wraps for free.

**The longest line.** Over all 5,401 code lines in the six corpus files, the longest is **107 characters** —
`cal-py-d6-004` in `python.json`, the `type_map` dictionary literal. `ui-monospace` advances about 0.6em a
character, so at `huge` that is 0.6 × 24 = **14.4px a character** and the line is 107 × 14.4 = **1540.8px**,
which is **3.25×** the 474.5px pane. It does not fit, and no pane that leaves room for the chat and the
preview would make it fit: at the shipped `0.95rem` (9.12px a character) the same line is 975.8px against the
old 383.6px box, **2.06×**. The line never fit. `word-break: break-word` was hiding that by breaking
`Callable` in half.

So the brief's fallback is the answer, and it is the normal case rather than an edge: `.vibe-line` is
`white-space: pre` and `.vibe-code` is `overflow-x: auto`. The share of corpus lines wider than the pane is
**31.6% at `huge`** (32.9 characters fit), **20.0% at `large`** (39.5 fit) and **7.8%** at the old `0.95rem`
(52 fit) — the median line is 24 characters and the 90th percentile is 49. Because a third of lines can
scroll at `huge`, the sideways scroll is not allowed to lose the caret: `keepCaretInView()` runs after every
editor redraw and keeps the caret at least 20% of the pane's width from either edge. It reads `clientWidth`
and returns when that is zero, so jsdom and a hidden pane are no-ops.

Every control is a `select` with an `aria-label` and a word for a value; no digit anywhere (G23). The
keyboard select moved out of row 4 into the settings row as the brief asks. The agent's name **stayed in

run — a name, a seed, go — while the settings row is the three things a player sets once and forgets. Mixing
them would put a text box in a row of selects and push Play further from the seed it reads.

Sound writes the same `muted` pref the field's own button writes, so the menu and the field can never
disagree: the select writes on `change` (so a player who sets it and walks away keeps it) and again in
`start()` with the rest of the patch, and `mountVibeTyper` reads `prefs.muted` at mount as it always did.

### The beat words

`BEAT_WORDS` is gone from `apps/cabinets/src/vibe-typer.ts` (slice 2's Decision 5). `cabinet.json` gained
`words.beats`, the loader requires all seven, each passes `lineFault`, and a missing or bad one halts with
`patterns/cabinet.json: words.beats.<beat>`. The shell reads `leversOf(state).cabinet.words.beats[state.beat]`
through the `words` it already had in hand, and `Beat` is no longer imported there at all.

Exhaustiveness is a compile error, not a runtime surprise: `BEAT_KEYS` is an object literal checked with
`satisfies Record<Beat, true>` and `BEATS` is its keys. Add a member to `Beat` and `patterns.ts` stops
compiling until the beat is listed and worded.

### Decisions

Where the brief was silent, the choice and the reason.

1. **`VibeOpts.font` is optional, not required.** The mount resolves `opts.font ?? prefs.font ?? DEFAULT_FONT`.
   This is the shape `muted` already has — the field reads it from the prefs, not from the caller — and it
   means a mount that does not care about type (every existing test, and any future embed) gets the player's
   own stored size rather than a hard-coded one. The menu always passes it explicitly, so the persisted value
   and the mounted value agree on the path that matters.
2. **`large` is `1.25rem`, and `small` is smaller than what shipped.** The brief asked for `large` to be
   visibly bigger than `0.95rem` and left the four numbers open. 1.25rem is a third bigger, which reads as a
   deliberate step rather than a nudge, and `huge` at 1.5rem is another third on top. `small` at 0.9rem sits
   just under the old default so that a player who wants more code on screen than v0.9.0 gave them has
   somewhere to go; if `small` were 0.95rem the word would be a lie.
3. **One property, three readers, and the scoreboard is not one of them.** `--vibe-font` is set on `.vibe`
   and read by `.vibe-code`, `.vibe-lines li` and `.vibe-beat`. The board's numbers and words keep their own
   sizes because they are the game's number and not text the player reads closely (G23), and the canvas is a
   picture at a fixed 480×360 — scaling type inside it would need the draw code, not CSS. Every rule uses
   `var(--vibe-font, 0.95rem)`, so a `.vibe` mounted without the property still renders exactly as v0.9.0 did.
4. **The `.vibe-beat` rule sits after `.vibe-head`.** Both selectors are one class, so the later one wins;
   `.vibe-beat` is declared immediately above `.vibe-code` and below `.vibe-head`, which is what lets the beat
   word take the type size while the chat and preview headers keep the 0.85rem label size.
5. **The wider grid is a `min-width: 1280px` query, not a change to the base rule.** Below 1280 the editor
   keeps its old share, because taking 90px out of a 289px chat pane at 1024 would make the chat the thing
   that wraps badly. The brief offered `fit-content` as an alternative; a media query is the one that can be
   reasoned about on paper, which is what this sub-slice had instead of a browser.
6. **The caret follows the horizontal scroll, with a 20% margin.** The brief asked only that a token never
   break. But `white-space: pre` means a third of lines at `huge` can run off the right edge, and a typing
   game whose caret leaves the screen is worse than one that breaks a token. `CARET_MARGIN` keeps a fifth of
   the pane clear either side so the next few characters are always visible before you type them.
7. **The spelling list lives in `src/spelling.ts`, not in the test.** The brief offered either; the source
   module is what lets the later authoring sub-slice import `britishHit` to reject a drafted line before it
   is ever written to a lever, which is the whole point of having the list. It is exported from the barrel
   beside the other gates.
8. **`code` is out of the spelling scan, and the two `cancelled` hits stand.** Reasoned above under the
   fixes. The test's comment says so, so the next reader does not "fix" the corpus.
9. **The corpus `topics[]` are scanned as well as `title` and `notes[]`.** The brief listed all three; worth
   recording that topics are a reader-facing surface too — the retro and a later reaction key read them — so
   a British spelling there would reach a player.
10. **The scan reads the shell's whole source text, comments included.** A British spelling in a comment is
    still ours, and it is cheaper to keep the whole file clean than to teach the test where the strings are.
    `main.ts` is the exception and is scanned only from `// ——— Vibe Typer` down, because Ghost owns the rest
    of that file and its spellings are not this cabinet's to change. The test asserts that marker still
    exists, so deleting it fails loudly instead of silently shrinking the scan.
11. **The sound control is a `select`, not a checkbox.** Every other control in the row is a select whose
    value is a word; a lone checkbox would need a label beside it and would be the only control in the menu
    whose state is not readable as text.
