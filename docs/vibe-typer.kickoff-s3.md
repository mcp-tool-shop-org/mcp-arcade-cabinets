## Decisions taken by the Director on 2026-09-15, after playing v0.9.0

Written as decisions with their reasons. Each changes the lock or the plan where it says so.

1. **The user's dialogue and the jobs are the product, and v0.9.0 shipped them thin.** The asks were templates tied to a snippet by its title, so the code rarely matched the request; the reactions did not know what had shipped; the eight levels were bands of four snippets, not stories; there were no nags. He judged this the part that carries the game and the part that fell short. This slice treats the lines and the jobs as load-bearing content: authored offline by a model built for writing, into the levers, with him reading a sample before the full run.
2. **The user checks in while you type.** Short interruptions during the code, of the "are you done yet" kind, land now and then. He liked this from the second draft and wanted it kept; what he refused there was the penalty around it. So: no context cost, no streak change, just the comedy and the agent's reply.
3. **Endless mode runs on a model, so that it is actually endless.** He had understood endless as model-driven from the start; a corpus walk with a noun list is not it. In endless the seated model writes the product, the asks, the nags, the reactions and the code the player types, behind a code gate. This amends G28 (below). The listed levels stay authored and on the corpus.
4. **American English on every surface a player or reader sees.** He does not want British spellings in his product voice. Twenty-two hits exist on Vibe Typer's surfaces today (six in `user.json`, three in the handbook page, two each in `products.json`, `agent.json` and the dispatch, one each in `levels.json`, `corpus/sql.json`, `corpus/csharp.json`, `vibe-typer.ts`), and the shipped level about the coffee machine's loyalty program is one of them. A test keeps them out from now on.
5. **A font-size setting.** The editor type is too small for a typing game. A settings row on the menu, persisted, applied to the field through one CSS variable.
6. **Visual work goes through Comfy MCP** (the `comfy-mcp` skill, the studio default for generation; every batch is a spend on his yes). Preview pieces per stack, a Vibe Typer logo for its package page, avatars, milestone cards, a backdrop. Rectangles stay as the fallback.
7. **More levels.** Eight is a demo. Sixteen or more authored levels, each a story about one product, plus the endless ladder.
8. **Builders are Opus subagents; no Fable subagents.** Fable is the coordinator only, because Fable subagents cost too much. Explore agents inherit the parent model, so pass `model` explicitly on every agent.

## Sub-slice B — the content pipeline (the load-bearing one)

Build `packages/vibe-typer/scripts/author.mjs`: an offline authoring script that asks a writing model for the user's and the agent's lines and writes them into the levers as **data**, reviewed and committed. Nothing in this sub-slice runs at play time.

**Which model.** Two routes exist on this rig: **OpenRouter** (`OPENROUTER_API_KEY` is set; the endpoint answered) for frontier writing models, and **Ollama Cloud** (`kimi-k2.6:cloud`, `deepseek-v3.1:671b-cloud`, `gpt-oss:120b-cloud` are pulled) at no per-token cost. The research says model humor sits below mid-tier humans and skews to novelty, so the pipeline is a draft generator with a human editor, not an oracle. Generate the same forty-line sample (ten asks for one level, ten nags, ten reactions, ten agent replies) from three candidates (one OpenRouter frontier model of the session's choice, `kimi-k2.6:cloud`, `deepseek-v3.1:671b-cloud`), put the three samples side by side in `docs/vibe-typer.author-sample.md`, and **stop for the Director's pick** before the full run. Record the pick, the model id, the prompt hash and the date in the slice doc.

**What gets authored.**

- **An ask for every snippet.** Each corpus snippet (249 today, plus every new one) gets its own ask, written so the request describes the job that snippet actually does, in the user's voice. The code the player types is then the thing the user asked for. Store it on the snippet as `ask` in `corpus/<stack>.json`; `{product}` may appear. The template pool in `user.json` becomes the fallback for a snippet without one.
- **Level stories.** Every authored level is four requests that tell one story about its product, in order: the first ask sets it up, the middle two escalate, the fourth is the deploy with a twist. Sixteen levels at least, two per stack plus integration, from easy to hot. `levels.json` gains `story` (a one-line premise the standup shows) and pins its four snippets by id instead of drawing from a band, so the story holds; endless keeps drawing.
- **Nags and replies.** Fifty short check-ins in the user's voice and the agent's replies to them, stored as `nags` and `nagReplies`.
- **Reactions per piece**, not per tier: a reaction that names what just shipped, keyed by snippet topic, with the generic pool as fallback.
- **Reviews per product**: the standup line names the product.

All of it passes the existing word gate (no digit, no barred word, one sentence, twelve words, nothing shouted) and the spelling test. Three candidates per slot from the model; the script keeps the ones that pass and the Director prunes on read. Every pool ends at least three times its slice-1 size.

**The nag mechanic in the sim.** A new event during a `code` beat: at a seeded interval from `levels.json → nagEvery` (seconds of frame time, jittered), never in the first request's first line, never during a sync or a creep, the user sends a nag (a `message` with `nag: true`); the agent's reply lands after the current line is sent; nothing else changes: no context cost, no streak change, no value. The shell pings it with the user's ping and a second, lower note. The band asserts the nag count per level stays inside a range and that a nag never changes valuation, hype or streak.

## Sub-slice C — endless on a model (amends G28)

**G28, amended:** in **endless** mode a seated model writes the product, the asks, the nags, the reactions **and the code the player types**, behind two gates; in the listed levels everything stays authored and on the corpus. Levels are the band's ground; endless with a seat is measured on its own bar with the seat swapped for the authored pool, as G11 says.

- **The seat.** Pull path through the launcher's tiered node-side seat (Claude by `ANTHROPIC_API_KEY`, else an Ollama cloud tag, else a local tag) and the dev server's `/cabinet/*` route, the same shape as Ghost's say seat. Add a `/cabinet/endless` route: given the product, the stack, the band, the last three asks and the player's weak pairs, the model returns `{ ask, code, title, notes[] }`. Prefetch the next request while the current one is typed (G13); a late, refused or malformed answer is the authored pool and the corpus, silently.
- **The code gate** (mechanical, in `packages/vibe-typer/src/codegate.ts`, tested): ASCII only; no tab; at most twelve lines and eighty columns; balanced brackets, braces and quotes; the stack's language by a cheap check from a table; no barred word and no model or tool name anywhere, comments included; a value from the difficulty formula inside the band's range, else re-ask once, else fall back. The gate never fixes a snippet; it accepts or refuses.
- **The chat gate** is the existing one, applied to the ask, the nags and the reactions.
- **Determinism and fairness.** The seed still owns everything the model does not write. `pnpm test:play vibe-typer --endless yes` runs with the seat off. `pnpm sit --cabinet vibe-typer` (extend `scripts/sit.mjs`, or a sibling) measures the seat live: how many asks, how many refusals per gate reason, latency per request, and prints ten sampled asks and their code for the Director to read.
- The shell shows, outside the field, which seat is sitting (the model name), as Ghost does. Nothing on the field names it (G17).
